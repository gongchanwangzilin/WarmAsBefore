WarmAsBefore × Touhou Little Maid

Minecraft 女仆桥 让存档里的角色，在 Minecraft 世界里有一具真的会行动的身体

温暖如初是大脑——人格、好感、信任、记忆、日程都在这里； 游戏模组是身体——坐标、背包、饥饿、挖掘、取水、投喂发生在方块世界里。 数值面板只显示，权威值在 WAB 存档；游戏里的每一次互动都会回到 WAB 的记忆层。

一、两台机器怎么对话

WarmAsBefore（大脑）
桥服务UDP 发现 + TCP 会话，收状态发指令
maid_* 工具 ×9聊天里 AI 直接调用
存档与记忆层好感/信任/记忆/NBT 快照
⇄UDP 27321beacon / offer
⇄TCP 27322NDJSON 帧
Minecraft Forge 1.20.1（身体）
WabBridge生命周期 / 会话 / 心跳
WabActions挖、舀、丢、喂、抱、放
WabAutonomy日程与随机自发行为

配对的五个步骤

  1. 选端口：插件设置 port（默认 27322，0 = 自动挑空闲口）。宿主启动时读取。
  2. 游戏里广播：模组每 3 秒向 UDP 27321 发 beacon（回环 + 广播地址都发，覆盖同机与局域网），带世界名、玩家名、女仆清单。
  3. 宿主应答：收到 beacon 后向来源单播 offer：TCP 端口 + 一次性 token + 30 秒证明（HMAC-SHA256）。
  4. 校验握手：模组连上 TCP 先发 hello（nonce + token）。宿主核对 token 与证明后回 welcome，绑定存档与角色。
  5. 开始协作：之后是常态循环——模组上报 state 快照与 event 事件；宿主下发 command（九种指令）与 stats；模组每 10 秒发一次 ping、宿主最迟 15 秒发一次，任何一侧 35 秒没收到动静就断开重来。
安全边界：token 30 秒过期且只用一次；默认只听回环地址，局域网要显式打开； 模组只执行白名单动作；JS 插件本身没有网络能力（清单里没声明 network / localnet， 出网的只有宿主桥服务这一条路）。

二、AI 能对她做的九件事

工具作用举例
maid_status她此刻的真实状况：维度、时间、天气、生命、饥饿、坐标、背包、附近玩家、爱恋数值“你现在怎么样？”
maid_scan环顾四周：附近生物、矿石、容器、作物、水/岩浆、亮度挖矿前先看看
maid_go真的走过去：to / near / follow / wait / home / wander，寻路不瞬移“来我这儿”
maid_gather动手采集：mine / collect / chop / harvest / scoop / fill，返回实际拿到的东西挖 16 个矿石
maid_hold物品与投喂：give / drop / take / feed_player / place / equip直接把食物喂给玩家
maid_act动作：attack / use / gesture / say / sit / stand / sleep / look / interact_addon主动抱抱
maid_plan一天的日程：几点去哪做什么、执行概率、空闲时的自发行为；由模组本地执行“晚上 9 点来喊我”
maid_bind把她绑定到某个角色；女仆太多时可以新建角色甚至新建存档每个女仆一个角色
maid_backup把她完整的 NBT（背包/状态/AI/日程）快照进 WAB 存档，保留最近 40 份大动作前留底

原则：不瞬移 移动靠寻路，太远会先 go； 不凭空造物 矿是真的挖出来的，进她背包； 不隔空取物 投喂要站在 3 格内； 可中断 每个长动作都有 tick 预算，超时返回已完成的部分； 一次只做一件 新指令会取消旧动作并如实说明。

数据权威方说明

五、能力声明与三道闸

这个插件的 JS 只用到三项能力，plugin.json 里就是这三条，一条不多：

能力默认用来做什么
settings允许读上面那几个开关，拼进人设。只能看自己的设置，看不到游戏设置和别的插件
prompt.write允许persona 钩子往提示词里加一段「你在 Minecraft 里有一具身体」
page允许就是这一页——用户点了才开，插件自己弹不出来

没有 tools、network、localnet、broadcast： 调工具、连游戏、写记忆全部由宿主的桥服务完成，JS 侧一个都不碰。

装了却像没生效，按这三道闸查

  1. 设置页有没有声明：settings.kind 必须是 native / html / none 之一，缺了的话所有钩子都不执行（插件中心那一行会写「不能运行」）。本页插件是 native。
  2. 这份存档放不放行它：存档高级设置里有插件白名单。同一个插件在 A 档能跑、在 B 档被跳过是设计如此；被跳过时会在 plugin_logs/wab_minecraft.log 留一行。
  3. 权限台里这几项有没有被改成禁止：prompt.write 设为禁止后 persona 钩子直接不跑，于是 AI 不再知道自己有身体——表现就是「桥连得好、工具也还在，但 TA 不提 Minecraft」。
预算：没声明等待型能力，钩子的时间预算是 300 ms。这个插件的人设钩子只做几次字符串比较与拼接，远在预算内； 等用户授权的那段时间不计入预算。

六、安装与联调

  1. 游戏端：把编译好的 touhoulittlemaid-*.jar（含 WAB 桥）放进 Forge 1.20.1 的 mods 目录；同一台机器上开世界，模组会在服务端每 3 秒广播 beacon。
  2. WAB 端：插件中心「从 zip 安装」或「从文件夹安装」（开发时改完 hooks/persona.js 直接重装文件夹最快），确认上面「设置」里 enabled 为开。
  3. 刚装好、一次「保存」都没点过时，settings.json 是空的——宿主与本页都按 plugin.json 里的 default 跑，不是按「关着」跑。
  4. 两边都在跑之后无需手动操作：握手自动完成。游戏内女仆头顶会出现行动栏提示（好感/信任），聊天里问“她在哪”时 AI 会自己调 maid_status 回答。
连不上先查：① 同一个 world + 同一个玩家；② 防火墙放 UDP 27321 与 TCP 端口； ③ 日志——WAB 在 logs/app.log（前缀 MaidBridge），游戏在 logs/latest.log（前缀 [WAB]）， 钩子层面的问题在 plugin_logs/wab_minecraft.log。 模组崩溃或 WAB 没开都不影响游戏本身运行。
