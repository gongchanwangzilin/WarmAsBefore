## A. 设定体系

### A1 ⚠️ 主设定 / 副设定分离

- 需求：拆成两份。主设定 = 不可变的人格基底；副设定 = 随时间和事件漂移的当下状态。新建角色时副设定是主设定的副本，此后只有副设定会变。
- 现状：不存在这两个字段。「主设定/副设定」仅出现在角色库编辑菜单的文案里，两个入口改的是同一份扁平数据。
- 要点：
  - `CharacterProfile` 拆为 `MainProfile` + 运行时 `SubProfile`，`CharacterData` 持有两者。
  - 副设定需要可回溯（至少保留最近若干次漂移快照），否则无法做差异展示与回正。
  - 副设定的写入方（AI 总结时自写 / 事件驱动）决定它进不进日记与回忆录。
- 依赖：与 C2（角色级设置覆写）共用同一套「全局默认 → 角色覆写」解析链，建议先做 C2 的结构。

### A2 ⚠️ 角色库只能规定主设定

- 需求：导入与编辑界面只允许写主设定；副设定归运行时；重复导入同一角色时不得覆盖已存在的副设定。
- 现状：导入路径（`ParseSettingTxt` / `ImportFromZipAsync`）写入的就是唯一那份 profile，重复导入会整份替换。
- 要点：导入需引入「主设定字段」与「运行时字段」的白名单，避免整份覆盖。

## B. 素材与画布

### B1 ⚠️ 立绘逻辑画布固定 1080×1920

- 需求：立绘标准画布为 1080×1920。尺寸不符的素材必须经调试界面处理（裁剪、翻转等）后方可使用。允许角色溢出画布，但三条硬约束：脚底基线对齐、缩放比例正确、朝向正确。
- 现状可复用：变换数学（脚位锚点、左/中/右归一化）、场景标定页 + 绘制层、像素尺寸探测（`ImageProbe`）。
- 要点：
  - 建议抽出共用的「立绘/背景标定」数据结构，供场景标定页与角色库/背景库两处入口共用，而不是两套实现。
  - 底部对齐与溢出的约束应写进校验器，非法素材明确报错而不是静默拉伸。

### B2 背景不做尺寸强限 + 空缺自适应填充

- 需求：背景任意尺寸均接收；游戏用周围的按键栏与信息栏自动填充空隙以适配；沉浸态没有周围栏时，空缺以纯黑填充。
- 现状：`HideDesktopPanels` 是「沉浸态」的载体，但它仅在桌面端生效，且隐藏后不留黑底。
- 要点：建议按短边等比缩放 + 余量黑底，UI 面板只负责遮挡；把「沉浸态」正式命名并扩展到手机端。

## C. 记忆系统

### C0 分层定义（需确认）

原需求表述为「加入两层」又说「5 层记忆结构」。整理后建议定义为：

1. **工作记忆** — 轮次上下文（现有 `MemoryTurns`）。
2. **人类记忆**（新增）— 事件、抽象、重要事件、单张图片；时间衰减；默认调取窗口三天内，可调至无限；可按角色单独配置。（AI 打的标签作为它的索引子结构，见 C4。）
3. **词义关系网**（新增）— 每角色一张词汇关联网。
4. **长时记忆库** — 现有 `MemoryVault`。
5. **档案层** — 日记 + 回忆录（现有）。

### C1 ⚠️ 人类记忆层

- 需求：模仿人类记忆方式编码/存储/提取；调取窗口默认三天内，设置页可调，最多无限；可按角色单独调。
- 要点：
  - 「三天内」建议实现为**距离加权衰减**而非硬过滤，否则三天外彻底不可见，与「会忘但不彻底忘」的目标矛盾。权重建议 = 重要性 × 时间衰减 × 复述次数。
  - 只存四类：事件、抽象结论、重要事件、单张图片（不存整段对话原文）。
  - 衰减与巩固机制参考：多存储模型（Atkinson & Shiffrin, 1968）、工作记忆四成分（Baddeley）、巩固与再巩固、睡眠期系统巩固与尖波涟漪、海马—新皮层交互。

### C2 ⚠️ 角色级参数覆写（前置结构）

- 需求：每个角色可覆写记忆窗口等参数以适配性格。
- 现状：无任何角色级覆写机制，`UserSettings` 全局单例。
- 要点：建立「全局默认 → 角色覆写」解析链，是 A1/A2 与 C1/C5 的共同前置，建议最先做。

### C3 ⚠️ 词义关系网

- 需求：后台自动为每个角色构建词汇关联网络；默认不消耗模型调用；可选参数模型辅助；人与 AI 均可实时纠错；检索时经关系网联想。
- 要点：
  - 默认实现为纯规则 + 统计（同现、共指、时间邻近），模型辅助作为开关。
  - 需定存储形态（JSON 邻接表 vs 本地库）与增边时机（每轮对话后离线增边）。
  - 纠错入口需落在回忆录或记忆详情页。

### C4 标签层

- 需求：AI 可对「人」「部分对话」「事件」打标签用于分类；支持单标签检索与标签组合检索；标签列表向记忆注入时放 10–20 个；标签本身可被回忆（多层嵌套）。
- 现状：无标签体系，也无组合查询。
- 要点：标签是跨层索引（可标注长时记忆与人类记忆），不建议作为独立存储层。

### C5 检索排序

- 需求：工具检索记忆时以时间近→远为主序，叠加随机扰动，模拟人会漏、会跳着想起。
- 要点：随机强度建议纳入 C2 的角色级配置。

### C6 日记 / 回忆录

- 沿用现有实现，明确其所属层与写入触发时机（现仅夜间定时），并按 A1 决定是否写入副设定漂移。

## D. Skills

### D1 ⚠️ Skills 导入与供 AI 使用

- 需求：可导入 skills 供 AI 使用，并能在应用内运行。
- 现状：只有工具与插件体系（内置工具注册表、外部插件 manifest、Android proot 沙箱、MCP 编排），**无 skill 概念**。
- 要点（需决策）：
  - 格式：走通用 `SKILL.md` + 目录（按需加载说明书，适合「教模型怎么做」）还是并入现有 `ExternalToolManifest`（适合「给模型一个可执行程序」）。两者可并存：skill 提供说明与资产，工具提供执行入口。
  - 导入源：本地 zip / 目录 / git 地址。
  - 权限：手机端沙箱未信任时是否禁用 skill 执行；是否纳入工具完整性检查（`ExpectedTools`）。

## E. API 与成本

### E1 模型使用顺序

- 需求：设置页可指定模型使用顺序。
- 现状：已有 `AiEndpointProfile` 轮换池，仅有启用/池，无有序列表。
- 要点：改为有序并可拖拽排序；顺序语义需明确（故障转移优先级 vs 轮换）。

### E2 超时时长可配

- 需求：设置内可调超时。
- 现状：硬编码 25s，仅全局。
- 要点：全局默认 + 每端点覆写。

### E3 ⚠️ 智能省钱

- 需求：录入模型价格后生成花费与 token 用量表；自动预测「再过两轮对话，现在总结 / 按某级别总结 / 不总结」哪个更便宜；识别是否处于编程/办公类工作以调整算法，避免盲目总结导致重复读取反而更贵。
- 要点：
  - 需先把现有单一折叠摘要拆为**分级**（不总结 / 轻折叠 / 重折叠），否则「总结级别」无对象。与 C 组强耦合。
  - 工作场景识别建议用轻量特征（关键词 + 工具调用形态），不额外调用模型，否则省钱逻辑自身产生成本。
  - 成本表需按端点分别计价（多供应商单价不同）。

## F. 平台与存档

### F1 手机端进入存档自动横屏

- 需求：手机端进入存档时自动切横屏。
- 现状：仅全局方向设置，进入存档不改变方向。
- 要点：进入存档锁定横屏、退出回正；与现有 3 秒自动回正逻辑协调，避免互相打断。

### F2 存档级可用角色

- 需求：为存档规定可用角色，避免角色库里只要有角色就疯狂添加配角。
- 要点：存档内维护「可用角色白名单」，注入提示词时限定只在名单内选配角；全局角色库与存档白名单是两层概念。

### F3 ⚠️ 过期存档自动修复

- 需求：过期存档自动修复。
- 待定：「过期」的定义需明确。建议按「存档结构版本号落后 + 加载校验失败」处理：引入版本字段，加载时按 schema 迁移并补默认值，迁移失败才报错。
- 要点：存档目前无版本字段，需先补，否则无法判断新旧。

### F4 AI 可选择黑屏

- 需求：AI 可主动选择黑屏应对某些时刻，但黑屏不代表不能对话。
- 待定：黑屏范围——仅关立绘与背景（保留 UI 与输入），还是整屏涂黑仅留输入。建议前者，后者需要额外的退出机制以免用户卡住。

## G. 外部接入

### G1 ⚠️ QQ 机器人增强

- 需求：可选是否回复群聊消息；可设定用户昵称 / QQ 号以识别用户，让 QQ 成为虚拟世界与现实的桥梁（典型场景：存档内让她用手机发消息，消息真的发到用户手机上）。
- 现状：已有 QQ 绑定角色的单值配置、群相关模块与微信式页面。
- 要点：
  - 群聊需白名单/触发条件，否则是噪声源。
  - 主动外发消息需频控与确认策略，且应与 D1 的 skill 权限模型统一，避免「任意工具可无限制发消息」。
  - 用户身份识别需要「昵称 / QQ 号 → 存档内用户」的映射表。

### 本轮刻意留白的部分（已知的「最小实现」）

以下不是遗漏，而是按现有结构选的最小可用做法，后续可单独提出：

- **副设定**只有规则推导出的心境与心事，没有「让 AI 改写性格」的路径；差异查看是文本摘要而非对比页面。
- **记忆分层**的 5 层命名只存在于本文档，代码里没有统一枚举，仍是若干服务各自实现。
- **日记 / 回忆录**尚未接入人类记忆层展示（数据已同源，界面未串起来）。
- **立绘标定预览**是近似对齐（基准线画在画框 90% 处），不是与游戏逐像素一致的预览。
- **词义关系网**没有「参数模型辅助增边」的自动路径，只保留了供人工与 AI 调用的接口。
- **花费表**是纯文本表，没有图表与导出。
- **主动外发**只做了 QQ 通道，微信通道未同步实现。
- **1080×1920** 是比例校验 + 标定闸门，不做强制重采样。
